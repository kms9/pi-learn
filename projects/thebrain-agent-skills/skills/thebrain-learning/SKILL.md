# Skill · TheBrain Learning Tutor

## 触发场景

用户希望“理解某个概念/项目”“基于已有资料系统学习”“用提问检查是否真正掌握”“复习遗忘点”。

此 Skill **不是自动生成百科文章**。要从 TheBrain 中已有内容与用户已掌握知识出发；回答以掌握/迁移为结果。

## 依赖及边界

- 通过 `brainctl search / thought graph / note get` 查找本机已有知识（具体命令见项目 README）。
- 使用 `docs/KNOWLEDGE-BEST-PRACTICES.md` 的事实/来源等级，不得把 AI 自产内容当成已存在的 TheBrain 证据。
- 学习状态：`learnerId + brainId + thoughtId + sourceVersion + attempts + lastResult + nextReviewAt`（SQLite 预留）。TheBrain Notes 不用于写个人答题明细。
- 本阶段学习可在**会话内**完成，持久化状态尚未实现；不得伪称学习进度已同步。

## 流程

### L0 · 目标澄清与范围

输出一个可以检验的目标，例如“能解释 Task Contract 与 DAG 的差异，并能在项目任务中正确应用”，而不是“读完多智能体文章”。

### L1 · 诊断

先问 1-3 道先验/迁移问题或让用户陈述理解。仅据用户实际回答给出初始掌握假设，不使用语气、信心或阅读时长假装测得掌握度。

### L2 · 构建证据上下文

调用本机 CLI 检索相关 Thought、Graph 和 Note；通过多跳关联找到先修知识、定义与反例。为材料标出 Thought 来源；引用冲突时显式列出，证据不足时要求补充而不是编造。

### L3 · 生成学习路径

路径基于依赖而非 UI 层级：`先修概念 → 当前概念 → 对照反例 → 应用任务`。先聚焦一个概念群，不把全部 Brain 文档塞进上下文。

### L4 · 解释与主动回忆

- 首次讲解：用通俗定义、技术细节、正例/反例、图谱中已知的关联。
- 立即回忆：不用看原文说出定义、指出错误例子、画出适用边界。
- 迁移应用：给出一个改变背景的新问题，检查是否能迁移。
- 如果回答错误：定位具体误解，退回相关先修 Thought，不直接刷更多同类答案。

### L5 · 评价与复习

为每一知识点记录：
- `correct`：通过或未通过，依据用户的实际回答；
- `confidence`：用户报告的把握程度，可选；
- `errorType`：遗漏/混淆/迁移失败/证据冲突；
- `nextAction`：重讲、对照学习、练习或延后复习。

P0 在对话中报告结果；M4 之后写入独立 SQLite 并探索间隔复习算法，禁止提前声称完成 FSRS/其他记忆调度。

### L6 · 建议知识回流（可选）

只有当发现知识库原内容确实缺少来源、存在冲突或重要定义缺口时，将“建议补充”交由 `thebrain-knowledge` Skill 先预览，学习 Skill 自身不擅自写 TheBrain。

## 示例

主题：“如何区分 Task Contract、Dependency DAG、Acceptance Gate？”

1. 先问用户：为什么一张 DAG 不能证明一个任务已经被正确完成？
2. 在 TheBrain 中检索三个 Concept Thought 及其证据。
3. 比较 Contract 的输入/交付边界、DAG 的依赖顺序、Gate 的可验收证据。
4. 用一个新任务让用户指出谁承担任务、谁等待谁、谁有最终验收权。
5. 根据答案识别误区：若把依赖完成当作验收完成，回到 Gate 解释并重新测试。
6. 总结掌握证据与下一次学习目标。

## 输出模板

```text
学习目标：
证据来源 Thought：
已经掌握：
存在误解：
本轮解释与测试：
用户实际回答：
评估依据：
下一轮主动回忆/迁移题：
学习状态：session-only / persisted（以实际实现为准）
```

## 验收

至少三个独立概念群，包含一次真实误答、一次边界/迁移题和一次证据不足情形；不得用“AI 认为用户已懂”作为验收标准。
