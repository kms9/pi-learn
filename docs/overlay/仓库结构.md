# 仓库结构

`pi_case` 是 **独立 overlay git 仓库**，不是 `earendil-works/pi` 的 fork。现有 GitHub 仓以 **submodule** 接入，overlay 只钉 commit SHA。

| 路径 | 层 | overlay 里记什么 |
|------|----|------------------|
| `docs/` | wiki | 全文 |
| `AGENTS.md`、`README.md`、`scripts/` | schema / 工具 | 全文 |
| `docs-zh/` | 译文镜像 | 全文 |
| `pi-dev/` 等 | raw / submodule | `.gitmodules` + gitlink SHA |

清单见根目录 `.gitmodules`。

## 更新到最新

本仓有两层，分开更新：

1. **overlay**（`docs/`、`docs-zh/`、`scripts/`、`.gitmodules`、各目录的 gitlink SHA）
2. **submodule 工作区**（`pi-dev/` 等上游 clone）

「最新」默认指各 submodule 在 `.gitmodules` 里登记的远程分支尖（`pi-dev` 等是 `main`，`deepseek-harness` 是 `master`）。Overlay 自己跟 `origin/main`。

```bash
# 0. overlay 工作区先干净，或至少不要和 gitlink 混在一次未看过的 commit 里
git status -sb

# 1. 把各 GitHub submodule 拉到登记分支的最新 commit
./scripts/sync-submodules.sh

# 2. 看哪些 gitlink 动了
git submodule status
git diff --submodule=log

# 3. 确认后在 overlay 里 commit 这些路径，才算钉死新版本
#    git add <动过的 submodule 路径> .gitmodules
#    git commit -m "Pin submodules to latest tracked branches."

# 4. 对照 pi-dev 译文是否过期（退出码 1 = stale / 缺文件 / HEAD 相对 manifest 漂移）
python3 scripts/sync-zh.py

# 5. 改完 docs-zh 对应文件后，接受新原文哈希并记下 HEAD
python3 scripts/sync-zh.py --accept pi-dev/packages/... --record-head
```

不要在 `pi-dev/` 等 submodule 工作区里改文件当 overlay 作品。译文只动 `docs-zh/`。

只想检出 overlay **已经钉死**的 SHA（不追远程分支尖）：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

协作者第一次拿齐源码：根目录 `README.md` 的 `git clone --recurse-submodules`。

## GitHub

推 overlay（含 `.gitmodules` 和 gitlink）。协作者：

```bash
git clone --recurse-submodules <overlay-url>
git submodule update --init --recursive   # 已 clone 过时
```
