# 2026-10-04 Pi Squad 的 Pi 1.0.1 规划与实施

## 用户要做什么

将适配评估中的 P0 和 P1 可靠收尾、请求证据、能力检测形成 OpenSpec 并实施。用户选择只支持 TUI；真实模型服务的 426 问题由用户修复后继续验收。

## 达成了什么

- [独立 change](../../openspec/changes/archive/2026-10-04-pi-squad-pi-1-0-1-compatibility/proposal.md) 交付 proposal/design/spec/tasks，19 个兼容场景；保留旧 `pi-squad-team-orchestration` 未完成事项，不归档或提交本 change。
- 1.0.1/TUI 注册前检查；九种控制工具 model-only + sequential、嵌套护栏、注入前完整工具验证；受管 ls 使用官方定义和既有片段/路径栅栏。
- 成功 completion/yield/clarify/answer/decision/正式 ask reply 返回 terminate，错误不提前终止；延迟 settled 捕获身份与 outcome，提交前重查 idle/pending、generation、session/binding。
- [请求证据模块](../../pi_squad/extension/request-evidence.ts) 使用 canonical 当前 sections/tools，与可识别 provider 的有效 system/tool 声明重放比较；历史 user/assistant 不证明当前身份，未知格式为 unknown。生产观察为 squad_hook，最后加载的 [schema 2 observer](../../pi_squad_case/04-team-orchestration/compatibility/pi-probe.ts) 才为 last_observer。
- Go doctor 增加 --pi-binary 与安装身份校验；真实有序生命周期与宿主匹配才可就绪。schema 1、不匹配身份、错误 sections/tools、pending 和乱序负例均不就绪；可选声明缺失不构成单独否决。

## 真实检查及限制

独立 npm Pi 1.0.1、Node v24.16.0、Go 1.27.0；全局 Pi 仍为 1.0.0。关闭旧测试 space 后在项目 cwd 新建 Herdr workspace，三个不同角色、Controller 与 Dashboard 直接观察。实际 `local-grok/grok-4.7` 验证了单独和混合收尾、正式 ask、Leader decision、父子 yield/clarify/answer、嵌套 completion 拒绝、请求历史误证与 unknown、/new 和人工输入中断的旧 settled 隔离。任务停止后所有测试 Attempt cleanup 均 released，测试 space 与临时控制文件已清理；未停止用户服务、未调用其他 Agent 协助。

针对实际安装的 TS 类型检查、Controller 编译和 OpenSpec 严格校验通过；按仓库规则不新增或运行单元测试。实际 schema 2 报告令 doctor 输出 formal_execution_ready=true。**兼容场景为 14 PASS / 5 PARTIAL**，细分断言和未覆盖格式见 [兼容入口与覆盖范围](../../pi_squad_case/04-team-orchestration/compatibility/README.md)；不把核心事件就绪算作原阶段 04 的 89 项全量通过。

首次激活 API 归属、文件工具白名单、空 section 哈希及验收夹具的错误已经修正并重新运行，旧失败保留在 ignored 集成证据目录。本次只更新 overlay 插件及文档，未修改上游源码、全局 Pi、模型配置或项目的业务角色/Team 配置。
