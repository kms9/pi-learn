# 2026-10-04 Pi Squad 的 Pi 1.0.1 TUI 范围

## 决策

用户明确选择「仅支持 TUI，明确拒绝 RPC 正式激活」。本次落地 profile 为 `pi-coding-agent/1.0.1`；RPC、JSON、print 及未验证版本在注册前拒绝 Squad，普通 Pi 仍可使用。未来版本需更新 profile 并重新采集真实运行证明，不用版本下界推断兼容。

本页在 2026-10-04 写回；对话未提供用户选择的独立时间戳，decision_date 保持 unknown。

## 背景

用户要求先形成 OpenSpec，再实施 P0 和 P1 的可靠收尾、请求证据、能力检测。系统全局 Pi 1.0.0 与已更新的 `pi-dev` 源码 1.0.1 是不同对象；本轮使用独立 1.0.1 安装验收，未升级全局安装。

## 证据

- 用户本轮范围答复；[OpenSpec proposal](../../openspec/changes/archive/2026-10-04-pi-squad-pi-1-0-1-compatibility/proposal.md) 与 [design D01](../../openspec/changes/archive/2026-10-04-pi-squad-pi-1-0-1-compatibility/design.md)。
- [激活检查](../../pi_squad/extension/doctor.ts)、[Invocation](../../pi_squad/extension/invocation.ts)；[真实覆盖记录](../../pi_squad_case/04-team-orchestration/compatibility/README.md)。

## 影响

- 保留现有 Controller 的 result/settled、停止确认与资源隔离；terminate 只结束本地推理。
- doctor 的实际安装诊断与核心事件观察分开；可选声明文件缺失不单独否决，schema 1 只能诊断。
- 末位 schema 2 的当前有效上下文证明不等于阶段 04 全量验收通过。

## 复审触发条件

用户要求 RPC 正式执行、新 Pi profile，或发现新增 provider 请求格式时重新规划并验收；不能通过普通 RPC 可用推导 Squad RPC 可用。
